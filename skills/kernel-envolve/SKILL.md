# Kernel Envolve

以 agent 的研究循环为主体：找真实瓶颈，选择最便宜的有效实验，有收益信号再扩大验证。目标是快、正确、适配实际输入范围的实现；管理、面板和归档服务于研究，不把每个尝试都变成正式评测。

## 启动与接续

- 每个新会话或管理轮次执行 `kernel-envolve update`，读返回的 Skill，并使用返回的 `executable` 绝对路径。本轮固定 Skill/CLI/evaluator；full → confirm → promote 之间不换版本。不要在算子工作区 `git pull` 升级工具。离线沿用可用版本，`disabled` 时使用本地代码，见[更新规则](../../docs/auto-update.md)。
- 先读任务 `notes.md`，核对源码、已有作业和未消费的结果，再选择下一项实验；不重建固定基线，不重复提交仍在跑的作业。保持独立 oracle、固定原始 baseline、已验证 best、探索 candidate 的区别。
- 首次确定真实调用路径、前反向/状态语义、尺寸与上下文长度范围、dtype/stride/offset/alias、精度门、硬件、执行模式与预算。长时间对照搜索前确认固定基线通过相关原生数值门；复用源码、契约和环境匹配的资格证据，不在每轮重做。基线 FAIL 时先定位实现或契约问题，不把 baseline 逐位一致当成数值合格。
- 直接使用目标 GPU 环境，不设固定 CPU 准备阶段。复用项目镜像、固定基线/输入及按源码与配置区分的编译缓存；版本、依赖或执行模式变化时才重验受影响部分。硬件或参考实现按需查[入口](references/hardware.md)。
- 内部项目首次接入时读[原生评测与适配接口](../../docs/native-harness.md#apodex-内部项目评测)，按实际两仓分支及 pin 处理；独立任务读[通用评测](../../docs/generic-evaluator.md)。只加载本次需要的细节。

## 每次尝试

1. **提出假设。** 从 trace、逐场景结果或源码定位瓶颈，写一句可被实验否定的机制与预期影响。优先计算组织、数据移动、融合、反向、布局与调用开销，不机械遍历参数。可从未晋升原型继续组合；用当前较优研究实现判断增量收益，同时保留原始基线，不把研究前驱当作合格 best。先估算目标占比和新增成本，避免为无法影响完整调用的微小信号反复全量评测。为本假设选一个有利输入和一个最可能否定它的输入；例如跳过无效槽位时，先测全有效槽位的额外成本。
2. **局部实验。** 选择能回答该假设的编译检查、原生 pytest node、独立 oracle、微基准或 profiler。先做受影响路径的必要正确性检查，再测代表输入；已知失败只重现对应输入。参数扫描可在一次有界作业内成批完成，复用导入与编译，逐候选保存结果。探索无需逐 case/角色重启进程；能显式调用两个实现时，可用 [research 工具](../../docs/native-harness.md#轻量研究工具)做同进程配对，正式验收仍隔离源码。DSA dQ/dW 可参考[局部探针](../../examples/apodex_dsa_research/query_probe.py)，只适用于单叶源码变化。
3. **及时取舍。** 错误或无收益时保存原因并换机制；同一候选的依赖阶段按结果决定是否继续，reject/inconclusive 不自动进入昂贵验证；独立候选各自筛选，不能因前一个性能拒绝而取消后者。CUDA/正确性异常先诊断，不在故障进程里继续。子命令必须检查退出码。有信号时先确认完整阶段包含 prepare/clear/repair 等真实成本，再检查公共前反向或实际模块是否受益。局部实验收益只作选路依据，不更新 best，不宣称训练加速。需要可信配对筛选时使用 evaluator quick；不强制每个探索候选先经过 quick。
4. **正式确认。** 有足够依据的候选才进入 full：固定原始基线和当前 best、原生精度门、广域输入与布局、各分支/fallback、逐场景退化、显存及实际调用链。随后使用未参与选择的输入确认，合格后晋升、更新中文 PR，并继续下一项假设。

每个探索实验只保留复现所需的代码版本/差分、输入与参数、环境、命令、退出码、原始结果和简短结论。固定依赖保存一次；下一次修改前保存当前候选差分，失败原型也可追溯。不为每个局部尝试复制整仓、运行全套原生门、重新注册任务、更新工具或启动新管理轮次。

同一源码、参数、环境和评测契约不重复提交，除非预先约定的重复测量、测量故障或新证据给出原因。inconclusive 不等于更慢，也不能通过反复抽样直到 PASS。没有可执行假设时重新检查瓶颈，不启动空轮冒充进展。

## 可信评测与交付

- 原生任务使用 `native-evaluate`，独立任务使用 `evaluate`。二者 quick 可选 `--case/--seed`；失败定位可加 `--check-only`，正常配对筛选无需先重复一遍 check-only。原生 `--mode full --check-only` 检查全部开发输入及原生门、不计时；验证固定基线时使用独立任务，将 candidate 指向基线副本。quick 与 check-only 均不晋升、不消费确认集。原生默认执行预算 quick 120 秒、full 1800 秒；超时是诊断信号，不是速度达标。冷编译单独记时，必要时显式设预算。
- **不削弱正确性。** 保留独立 reference/golden、前向及相关梯度、输入/状态/输出结构检查、既有数值与 bitwise 门槛。原生 U/z 等门与 baseline parity 分别记录。旧 FAIL 不删、不豁免；严格 FP32 与已声明 BF16 契约分别验证。确需修正契约时独立审查并建立新任务，不修改旧报告。
- **覆盖真实泛用范围。** 用代表点、非对齐尺寸、不同输入的独立 stride/offset、dispatch 边界和 fallback 检查泛化；允许合法 shape/dtype/layout 分发，不按固定种子、输入地址或评测次数投机。仅增加 seed 不算尺寸泛化。
- **测量口径一致。** 对照使用等值输入、权重、梯度及可变状态，按生产语义恢复状态；独占 GPU，预热后交替配对计时。包括真实调用中的准备、布局转换、分配和同步；eager/Graph 分开，通信优化在实际多卡链路验证。单独 profiler 的 replay 耗时不作性能结果。
- **源码与证据绑定。** 正式 evaluator 仍完整冻结、哈希并隔离角色源码；不以 mtime 缓存或跨角色硬链接代替。使用节点本地盘进行快照与临时交换，完整 run 在验收/交付边界持久化；局部探索仅做上述轻量记录。退出码成功不等于可晋升，核对本轮报告、非零测试数量、必需 rank 和真实后端调用，排除旧记录、意外 skip 或 fallback。
- **独立确认。** 内部任务预先声明 `confirmation`，full 合格后执行 `native-confirm <run>`，再 `native-promote <run>`；独立任务用独立验证任务确认后 `promote <run>`。已经观察或用于修改候选的留出样例转入回归，不再作为未见输入。内部确认集每任务只能消费一次，失败/中断或换候选不重用，见[确认规则](../../docs/native-harness.md#独立确认)。

性能结论须有测量证据。叶子、完整阶段、公共 F+B 和训练 step 的收益分别表述；逐场景给出原始延迟、加速比及最差退化，不相乘不同实验的收益。总体按任务权重汇总耗时后计算，缺少真实权重时分场景报告。

## 资源与持续运行

管理器用于多任务、设备互斥、预算及恢复；单会话研究不要求先部署面板或 bridge。在已管理的任务中，所有 GPU 命令（包括访问 GPU 的编译、测试、profiler、局部实验）必须经过：

```bash
kernel-envolve manage gpu-run --expected-seconds <预算内预计秒数> -- <原生实验命令>
```

它可直接执行现有实验脚本，不强制调用 evaluator。一次有界命令可包含多个相关候选，禁止嵌套或留下后台 GPU 进程；设备与累计预算由管理器控制。若使用前台 bridge，同一请求可执行这批实验，及时消费结果，不把 ready/heartbeat 当作 agent 进展。提交后还有独立源码分析可做时用 `--wait-seconds 0` 先返回；需要结果时使用 `bridge-request --wait-seconds 30`，完成即返回；pending 时接续同一 ID 等待，不在状态查询之间固定 sleep，也不重复提交。需要模型解释才能选下一步时，在该决策点结束有界批次并返回证据；stdout flush 不代表远端日志已送到模型。CPU 分析不占 GPU 队列，失败 CUDA 进程不能复用。管理方法见[管理层](../../docs/optimization-manager.md)。

沿用一份简短 `notes.md`：当前候选/最佳版本与证据、已尝试机制、下一项可执行实验、运行中作业、PR 与累计额度。管理轮次结束时写 `KERNEL_ENVOLVE_REPORT`（hypothesis、outcome、next_action）；正式速度由 evaluator 证据提供，局部结果写 outcome 并指向原始记录。不要为每个参数点创建管理轮次或强制等待面板刷新。

在实验批次结束、交接或资源释放前，将新增局部记录及正式 run 持久化，并保存 manager 一致性备份；不能把仅有 JSON/日志的摘录称为完整源码备份。仅保留需要复现或诊断的输出张量，避免每轮复制相同基线输出；不可丢弃正式证据。归档不重复打包整个历史，已经压缩或高熵的大文件不做高等级重复压缩；不得在证据未保存时回收唯一副本。

一次晋升或多轮无收益不结束持续优化；在已授权算子范围和额度内继续。用户暂停、累计预算用尽或外部阻塞时保存证据并释放闲置资源，不扩大授权、不复活终态任务。跨会话唤醒依赖真实宿主执行器，不能靠一句“不要停止”实现；用户禁止自动化时前台主动续接。

## 收益 PR

确认完整正确性、调用链收益和独立输入后，自动创建或更新本任务自己的实现 PR，不等优化彻底结束；已存在同一算子/目标分支的未合入 PR 时继续更新它。先查远端状态，不接管其他任务 PR。后续探索使用独立候选，PR 保持已验证版本。

使用目标仓库模板，中文说明具体问题与实现变化，列出硬件/软件、源码版本、计时范围、主要场景和最差退化的收益表、正确性与复现证据。延迟下降为 `1 - candidate / baseline`；加速比为 `baseline / candidate`。更新时重写当前收益，不将旧百分比与新百分比相减。通过 `gh --body-file` 保留真实换行；kernel_envolve PR 执行 `tools/check_pr_body.py`。

交付源码及 helper 必须与已验证快照一致；冲突或行为变化后重验。内部按项目规范处理 core 实现、Megatron 接线和 pin，核对实际调用。发布后查询 PR head/状态；管理任务在晋升后执行 `manage refresh --task <id>` 主动核对当前算子，再用 `manage sync-pr` 绑定实现 PR，不等后台面板刷新。修复系统流程的 PR 不冒充算子收益 PR。

## 验证系统是否有价值

不以测试数量、管理功能或超时设置证明优于裸 agent。同一算子、基线、硬件、模型、输入与预算下比较：候选提交到反馈的端到端耗时（含准备、归档、回传）、有效假设验证数/卡时、首次可靠收益耗时、完整调用链收益与回退、正确性和人工介入次数；环境冷启动与稳态分别记录。使用相同的结果验收规则，保留失败和全部尝试，避免两组共享已经观察的确认输入。

目标是在不增加探索成本的情况下提高正确性与交付可靠性；实际比较没有优势时继续简化热路径，不宣布系统胜出。新对照实验另按用户已有授权与预算执行。
