## 已完成对照说明了什么

最新**完整**自适应开发实验采用 4 个已知公式 × 2 个新配置 × 2 次重复 × 4 组，共 64 份独立最终 full，正确性全部通过。质量分数包含性能晋升条件，不是 kernel 加速比。各组都有 16 个试验。

| 组别 | 完整 trial 总耗时（秒） | 平均质量分数 | tokens |
| --- | ---: | ---: | ---: |
| 原无记忆四步 | 1272.060 | 0.357254 | 639,170 |
| 固定复用两步 | 633.983 | 0.321156 | 153,581 |
| 固定复用四步 | 1162.716 | 0.364585 | 613,772 |
| 自适应复用（预先指定的候选） | 797.302 | 0.336366 | 321,869 |

自适应候选的优化耗时 **−37.32%**、tokens **−49.64%**，但质量分数 **−5.85%**，违反逐任务和逐重复保护。结论是**该方案不合格**，独立确认关闭。没有事后改选固定复用四步；该消融的质量分数 +2.05%、耗时 −8.60% 也未达到 10% 实用门槛。

这说明复用有节约搜索的潜力，但“已有候选的通过余量”不足以判断继续探索的边际价值。也不能把所有退化都归因于提前停止：一项失败在保留四步的 RMS 上出现，独立 final 仍拒绝其性能退化。不同时间的观测不能单独区分计时波动、环境漂移和适应性原因。更早的文本经验、完整 episode 和固定两步研究也没有建立相对原系统的完整收益证据，见 [逐批历史记录](rsi-design-review.md)。

## 最后一次成果进化研究的边界

首次代际采集因旧 seed 的 evaluator 身份与当前版本不符而失效：运行时正确回退，却导致预期的复用处理未生效。已停止该批，全部成本保留；修复为创建注册表时提前拒绝旧 evaluator seed。此后固定四份**原始历史源码**重新 full 验证并独立 final，全部通过；零模型调用，未选择失败批中的赢家，也未篡改历史快照哈希。这是兼容性迁移，不是收益。

修复后的学习阶段完成 8 次研究、19 次模型调用，候选由真实 agent 的新源码形成：

- Swish：大规模跨步 FP32 输入使用已有融合 Triton 路径。
- Smooth L1：大规模 FP32 的 block 从 1024 调整至 4096，并使用连续输出分配。
- RMS：将 BF16 转 FP32 与平方融合，均值仍使用 Torch。
- Variance：没有选中符合条件的新源码，保留原实现。

后续原定 64 次的 control / seed / parent / candidate 四组准入由用户要求中途停止。保留 **92 次完整模型调用**，但它们不是 92 次独立最终评测，也不能据此计算准入通过率。立即停止后未收回完整远端 evaluator 归档，无法完成预注册分析；因此本阶段为**用户停止、结论未完成**，不是通过，也不是已证明质量失败。候选未采用，不能从部分日志选报正收益。

## 设计判断与实际价值

目前值得保留的是证据收集、局部候选形成、独立准入和回退机制，它们使后续研究能识别错误、拒绝退化和追溯成本。这是工程资产的用途，不是已经测出的生产效率收益。

分工上，执行 agent 继续正常做算子研究并留下既有记录；后台确定性收集已有收据，低频形成候选并独立验证。无需每次动作额外调用反思模型，也无需持续运行另一个 agent 翻日志。当前 artifact 生命周期提供后台 API，尚未加入生产 Manager 的自动成果收集与发布挂钩。只有完整证据和事前门槛通过才有采用资格，形成源码更新本身不触发发布。

资料中的候选档案、轨迹反思、增量经验、回放和能力保留值得分别吸收；本实现选择了更窄的改动权限和更强的采用约束，也牺牲了开放探索能力。过严准入可能限制发现速度，仍需独立实验判断；不能为了给本轮制造正结果而调整旧门槛。[参考工作表](rsi-design-review.md#参考工作与选择) 保留首发与版本日期，后续补充覆盖至 2026-11-09 首发资料；没有完成与这些算法的同预算复现对照。

后续若另行恢复研究，关键证据应是：冻结预算与独立保留任务上的完整收益、跨两代的原能力保留、重复错误率与有效结果产出率，以及包含学习和验证成本的回本分析。当前不启动这些工作，也不自动消耗剩余历史预算。
