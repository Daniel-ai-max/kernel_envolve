# 自动跟随 main

自动更新发生在使用边界：普通 CLI 命令执行前、手动会话开始时，以及管理器启动每轮 Agent 前。检查目标固定为官方仓库 `main`，无需等待版本号变化。仅获取帮助、导入 Python 库和评测 worker 不触发更新。

## 日常使用

```bash
# 启动新会话，检查更新并固定版本
kernel-envolve session -- <agent命令及参数>

# 已运行的 Agent：获取本轮入口和 Skill
kernel-envolve update

# 查看最近检查，不联网
kernel-envolve update --status
```

`update` 返回 `revision`、`release`、`executable`、`skill` 和状态；没有可用缓存时可能只有状态与错误。Agent 读取 `skill`，随后用 `executable` 运行本轮命令；相对引用以该 Skill 所在目录为准。固定入口中的 `update` 返回当前提交，不再切换版本。开始下一轮时使用最初安装的 `kernel-envolve` 入口重新检查。

`session` 将固定版本通过 PATH、PYTHONPATH 和环境标记传给 Agent、评测器及子进程。同一个 full → promote 必须使用同一入口；直接在两个未固定的命令之间更新评测器，会触发现有证据身份检查，需要重新评测。首次离线、尚无缓存的 `session` 也会固定使用已安装版本，避免联网恢复后在轮次中途切换。

管理器在每轮启动前重新检查，恢复提示记录完整提交、Skill 路径和命令入口；GPU 包装器及其子进程继承本轮版本。协调器和 Web 服务自身保持启动版本，更新它们需要正常重启相应进程；暂停与恢复规则见[管理层文档](optimization-manager.md)。

## 更新与失败处理

1. 获取本机更新锁，将远端 `main` 拉取到工具自己的 Git 缓存。
2. 按完整提交创建独立源码快照，检查 Python 版本、核心依赖、Skill 和 CLI 启动。
3. 验证成功后原子切换当前指针；未完成或失败的快照不会被其他 Agent 使用。
4. 保留旧快照，运行中的会话继续使用原提交。后续新会话采用新的 `main`。

各次未固定的调用都检查远端，不使用分钟级检查缓存；已固定会话不重复联网。更新锁最多等待 30 秒，Git 单步最多 15 秒，CLI 启动检查最多 30 秒。多个 Agent 同时使用时串行准备，只发布完整版本；中断留下的未发布目录会在下次使用时重建。

| 情况 | 行为 |
|---|---|
| main 未变化 | 复用相同快照，不重复构建 |
| 断网、拉取超时、新版本启动失败 | 保留上次可用快照；首次没有缓存时运行已安装版本，stderr 说明原因 |
| Python 或核心依赖不满足 | 保留可用版本，输出缺失要求；在项目环境中解决依赖后，下次自动重试 |
| main 历史被强制改写 | 保留当前版本，报告历史不连续，避免自动降级 |
| 本地仓库存在改动或处于功能分支 | 本地文件保持原样；自动模式执行缓存中的 main，开发本地代码时关闭自动更新 |

更新不运行 pip、不修改 PyTorch/Triton/CUDA，不修改算子候选、baseline、评测契约、已验证 best 或管理数据库。使用调用方的 Python 解释器和依赖环境；`packaging` 用于检查新提交声明的核心依赖。检查通过表示版本可启动，实际任务仍经过原有正确性和评测验证。

## 配置与维护

| 环境变量 | 用途 |
|---|---|
| `KERNEL_ENVOLVE_AUTO_UPDATE=0` | 禁用自动获取，使用本地代码；在固定会话内仍保持其已选版本 |
| `KERNEL_ENVOLVE_UPDATE_CACHE` | 缓存根目录，默认 `~/.cache/kernel-envolve` |
| `KERNEL_ENVOLVE_UPDATE_REMOTE` | 可选的受信任 Git 镜像，仍读取其 `main` |

缓存按远端、Python 解释器路径及版本隔离；每个缓存包含 Git 对象、提交快照、当前指针及最近检查结果。`KERNEL_ENVOLVE_RELEASE` 和 `KERNEL_ENVOLVE_UPDATE_SESSION` 是内部会话标记，由工具传递。不要手动修改快照；旧快照不会自动清理，清理前结束使用该缓存的全部会话与服务。

首次安装依然使用 README 的安装命令。旧安装和旧版复制 Skill 不会自行获得新机制，需要先更新到含此入口的版本，并更新一次复制的 Skill。此后由入口自动跟随 `main`；未合并到 `main` 的 PR 不会分发到下游。

回归测试使用本地 Git 仓库，覆盖新提交、并发调用、失败与离线回退、历史改写、依赖不兼容、中断恢复，以及会话/子进程固定版本；不依赖外网。
