# RSI 设计复核：适用性、代价与证据

复核日期：2026-11-10。结论：当前方案是针对 kernel_envolve 的有界经验进化实现。它将稳定发布、验证成本和可撤回性放在优先位置，但没有证据证明全面优于参考方法。论文报告的收益也不能直接迁移为本项目收益。以下“适合”是基于现有代码与工作负载约束的工程判断。

## 目标与优先顺序

希望相同资源预算下，减少相同条件下重复发生的无效实验，更快获得经过完整验证的有效 kernel。策略数量、反思篇幅和通过验证的策略数量都不是最终目标。

优先级是：保留正确性和独立 evaluator → 保留既有能力 → 限制生产路径和后台资源开销 → 改善验证过的优化结果。只有在前几项成立时才追求学习速度。采用门槛应在实验开始前冻结，不能由学习器为自己的候选降门槛。

## 本轮发现并修复的准入问题

旧规则要求每轮至少一项任务出现收益，同时每项退化不超过容忍值。这个逻辑存在反例：16 项任务，control 的质量均为 0.4；candidate 一项为 0.411，另 15 项为 0.381。局部增益超过 0.01，逐项损失小于 0.02，但平均质量从 0.4 降至 0.382875，旧规则仍会接受。

类似地，一项 solver 从 10 秒降到 5 秒，另 15 项从 10 秒增到 100 秒，总成本从 160 秒升到 1505 秒，局部成本胜出仍可能通过。质量显著改善也不应成为无限增加迭代耗时的理由。

新规则在每一轮独立检查：完整配对、有限有效指标、所有 candidate 正确、逐任务质量保护、整体平均质量不降、solver 和完整 trial 总耗时不突破固定容忍比例；然后才检查整体质量收益、正确性修复或整体成本节省。正确性失败的负数标记不作为数值收益参与平均。新收据包含逐轮汇总，既能审计，也避免用跨轮平均掩盖不稳定表现。

默认 5% 成本容忍是可配置的工程起点，尚无实测噪声依据。每轮两次重复是最低配置，不是统计显著性证明。该规则限制稳定发布，不证明它是最高效的探索准则。

## 已建立的边界及其限度

| 边界 | 当前保证 | 限度 |
| --- | --- | --- |
| 变更权限 | 候选 schema 只接受条件化建议；生产 evaluator、kernel 门槛、预算不属于候选修改对象 | 自然语言建议仍可能让 solver 作出错误选择；最终 full evaluator 和隔离部署仍必要 |
| 结果权威 | 由控制器独立调用 evaluator 并检查收据，不接受 solver 自报成绩 | 可信同用户适配器能访问宿主文件；文件哈希不能抵御恶意同权限进程 |
| 生产路径 | 每轮一次有界本地文件读取，无学习调用或数据库等待；故障回退原路径 | 文本仍增加模型输入，文件读取微基准不代表完整迭代延迟 |
| 后台成本 | 冷却、增量窗口、累计预算、崩溃保留预留额度、独立 GPU | CPU/内存/API 配额共享可能竞争；wall time 不等于 token 或金额预算 |
| 泛化 | 独立路径的冻结任务、重复配对、按 scope 发布 | 路径不同不保证语义不重叠；反复使用固定 suite 会过拟合 |
| 回退 | 谱系、证据审计、停用、恢复上一策略 | 不是对线上效果持续 A/B 的自动回退；后台停止时不会持续发现证据失效 |

暂不扩大到任意自改代码、模型训练、自动调低正确性门槛。这些能力需要新的隔离与评估条件；现阶段加入只会扩大未经验证的变化面。

## 下一步怎样证明“值得使用”

比较应固定任务划分、模型版本、可用工具、生产 solver 预算和总资源预算，至少包括：原始系统、同长度人工固定策略、只检索原始经验、当前局部经验进化。之后加入按官方机制实现并明确适配差异的 ACE / GEPA 基线；具备搜索树记录后再比较 Dream-RSI。不能把简化的检索或反思基线命名成原论文算法。

按算子家族、布局/形状和设备划分学习集、用于选策略的开发集、最终独立审计集。审计集在策略冻结后仅用于最终比较，不能把失败结果反馈给同一轮选择再报为独立测试。模型与硬件变更分别评估迁移，不合并宣称普遍有效。

提前冻结指标与判定方法：

- 正确性与保留能力：逐任务配对结果，所有失败和退化均保留，不能只报总分。
- 产出：固定预算内可晋升 kernel 的比例、质量分布；到达预先设定质量的耗时，超时作为未达成记录。
- 重复犯错：按错误类型、任务条件和已尝试修复共同定义，人工抽查归类，避免把同一报错字符串误认为同一种错误。
- 成本：分别报告生产 wall time、模型 token/费用、GPU 时间、学习和策略验证费用，另报实际并发下的端到端吞吐；不能把并行资源秒数直接当成端到端延迟。
- 不确定性：先用小规模 pilot 估计方差，再固定独立任务数和重复数；置信区间以任务为单位配对重采样，避免把同一任务的多次运行当成独立任务。固定分析次数，不能边看结果边无限补试。

学习一次是否划算，需要在同一种资源成本单位下核对：后续适用任务数 × 单任务平均节省，是否超过学习与验证的额外成本。若只能提升质量，则比较同总预算的质量；不能用独立 GPU 掩盖总账增长。若复杂 RSI 未胜过固定策略或简单检索，应保留更简单的方案。

截至首次设计复核，只有 CPU 闭环与反例测试。随后完成的真实模型/GPU pilot 见下文：它验证了拒绝无收益策略的流程，没有证明学习收益、生产迭代不变慢或方法全面领先。

## 试跑准备中的资源控制反例

用户随后允许在 HyperPod flexible、优先级 80 使用最多八张 GPU，并选择先用 gpt-6-astra 做一张 GPU、30 分钟内的试跑。模型连接测试成功，但开发实例启动期间，独立本地计时器在期限到达后因 DNS 失败退出，未能发出 stop。恢复观察后立即停止并核实空 Pod，创建请求到确认释放的保守计时为 6511.07 秒，超过约定期限。没有完成学习或配对验证，不能将这次资源消耗记为有效实验。

这个反例说明“进程有预算、本地有 watchdog”不足以保证云资源安全。后续试跑改为平台 `activeDeadlineSeconds`、禁止重试的批任务，模型凭据留在本机，任务只接收签名的响应；模型中转连接丢失也会提前结束工作。最初的 1200 秒替代方案仅做预览。用户随后明确批准 90 分钟，实际批次与修复尝试的累计资源账见下文；这不抹去此前超时事故。


## 2026-11-10：真实模型 / B300 小规模试跑

冻结源码 `983f3bd4cf2b93cedea86befdc1408a45d2f8eee`，模型 gpt-6-astra、medium reasoning；HyperPod flexible，1 张 B300、优先级 80。学习任务为 add-scale 和 row-sum，独立路径上的验证模板为 fused-ReLU 和 row-mean，各有连续/跨步布局、两组输入种子。验证为两模板 × 两轮 × control/candidate，共八次独立 full evaluator。Solver 每次只生成一个实现，没有多步工具调用；这只能检查接入、迁移建议和准入流程，不能直接测量“更会安排实验”。模型接口不提供配对随机种子，repeat 标签不能声称是相同的模型随机流。

两项学习任务均通过正确性，但基线加速比分别约 0.633 和 0.504（小于 1 表示更慢）。学习器收到两个 evaluator 事实和两条标为 Agent 解释的报告，提出“发生跨布局、跨批次性能回退时先诊断基线相对延迟”的建议。建议条件还点名了学习任务，能否迁移至验证模板存在明显限制。

| 指标 | 第 1 轮 control / candidate | 第 2 轮 control / candidate |
| --- | --- | --- |
| 正确性通过 | 2 / 2 | 2 / 2 |
| 可晋升 kernel 数 | 0 / 0 | 0 / 0 |
| Solver 总耗时 | 42.91 / 48.51 秒（+13.03%） | 39.71 / 44.52 秒（+12.12%） |
| 完整 trial 总耗时 | 49.85 / 54.84 秒（+10.01%） | 46.04 / 51.21 秒（+11.22%） |

准入拒绝该策略，active 保持 base，结束时禁用实验状态；没有生产策略发布，也没有修改 kernel 晋升门槛。八次验证的质量分数均为 0，表示没有满足原 evaluator 的晋升条件，**不表示所有 kernel 实际速度相同**；逐次基线加速比和原始收据仍保留。两轮延迟样本无法将成本差异因果归于建议文本，但已不足以通过事前固定的 5% 成本上限。学习耗时 13.65 秒，策略验证 201.95 秒。

这次 90 分钟授权下的三个批次从创建请求到确认释放累计 391.54 GPU 秒（约 6.53 GPU 分钟），均单卡顺序执行。第一批因 quick/full seed 配置不兼容退出，没有模型调用；第二批将 Triton 的正常 `tl.load` 错误拦截，完成一次模型调用后退出；第三批修正适配器，复用第二批的同一回答，不重新抽样，完成全部流程。模型实际调用共 11 次，14,844 tokens。平台报告的 cost 字段合计 0.3040865，币种未独立核验，不据此宣称账单金额。此前独立的 108.5 分钟事故仍另记。

最终批次配置 3600 秒平台硬期限、3300 秒 worker 期限、断联 60 秒退出、零重试、无持久生产挂载。平台预览与 live 配置一致，最终 live Pods 为空；所有批次提前结束，因此没有测试“到期时平台确实杀死任务”的情形。证据压缩包 SHA-256 为 `542021a732b3249cf71cd204eb2fec0143151a1bb65e42495b8ba12ba5a0ab8e`。本地独立重算了十份 evaluator 收据及策略准入结论。结构化记录见 [pilot audit](../audit/rsi_gpu_pilot_20261110.json)。

## 从失败试跑中吸收什么

这轮结果支持保留准入门槛，不支持把策略发布出去。它也暴露出当前输入摘要过粗：只给出“slower”和截断原因，会迫使学习器重复提出“先测量”的泛化建议。后续实现补充了 evaluator 已验证的 baseline/incremental speedup、最多八批固定基线收益、晋升资格及截断标记；缺失和非有限值保留为未知。它只扩充后台有界摘要，仍受 128 KiB 学习输入上限约束，不读取额外历史文件，不改变前台路径。旧证据不被悄悄重写。

另外，验证中的候选与生产建议都使用中性的“Scoped research advice”，避免把尚未通过验证的候选提示称为“Validated”。这会改变 validator 身份，旧收据不能沿用来采用策略。上述两处改动通过 44 项 RSI 测试及全仓 247 passed / 8 GPU opt-in skipped；**尚未再做 GPU 学习收益比较**。CPU 生命周期测试固定其报告的 solver 时间以避开短进程 25 ms 轮询抖动，真实适配器和 evaluator 仍执行，成本门槛由独立数值反例测试覆盖；真实 GPU 数据不做任何平滑或替换。

下一阶段应先让 solver 能在固定预算内实际执行“测量—诊断—改写—再测量”，记录每次假设、选择及失败原因，并与同工具、同预算的无记忆和简单检索版本比较。量化摘要只是更完整的观测，不是已经获得诊断能力。建议适用性、跨任务语义覆盖、最终独立审计集和学习成本摊销仍是未完成项；不应通过反复重跑同一候选、降低门槛或增加策略文字来制造“进化成功”。
