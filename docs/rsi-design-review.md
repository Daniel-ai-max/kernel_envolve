当前收益验收：最新 64 次 B300 对照中，直接成果复用相较无记忆通过原质量/成本门槛，质量分数提高 7.23%、trial 耗时少 5.59%；但未通过事前 10% 实用收益门槛及相较精简源码提示的成本保护，尚未采用生产策略。详细结果见文末。

复核日期：2026-11-10。结论：当前方案是针对 kernel_envolve 的有界经验进化实现。它将稳定发布、验证成本和可撤回性放在优先位置，但没有证据证明全面优于参考方法。论文报告的收益也不能直接迁移为本项目收益。以下“适合”是基于现有代码与工作负载约束的工程判断。

## 目标与优先顺序

希望相同资源预算下，减少相同条件下重复发生的无效实验，更快获得经过完整验证的有效 kernel。策略数量、反思篇幅和通过验证的策略数量都不是最终目标。

优先级是：保留正确性和独立 evaluator → 保留既有能力 → 限制生产路径和后台资源开销 → 改善验证过的优化结果。只有在前几项成立时才追求学习速度。采用门槛应在实验开始前冻结，不能由学习器为自己的候选降门槛。

## 失败范围的证据补全（2026-11-10）

新增混合精度训练轨迹中，第一次错误只出现在较宽的 bfloat16 case；随后仅对较宽输入保留安全实现，较窄 case 又出现数值失败。这说明“第一个报错没点名某形状”不能推导出它已通过。原始 evaluator 已保存具体失败检查，但后台学习投影此前主要保留错误文字和 Agent 报告，丢失了结构化的失败条件。

Manager 的 generic 收据投影与可选研究执行器现在提供 `failed_checks`：最多八项已观察失败、对应 frozen task case 的参数（每项最多 512 UTF-8 字节）、总数和截断标记。参数超限时保留未知，不截断成可能误导的半份对象。投影在原收据和源码核验后生成；改动当前工作目录中的 task 配置不会改变历史证据。结果明确说明 evaluator 可能提前停止，未列出的 case 是未知，而非通过。旧索引缺字段、native 检查契约不适用时保留未知，不伪造为零失败。

这些信息只补充后台证据和可选研究工具反馈，前台仍读取同一个有界建议快照。第一轮开发对照冻结于 `a77bad3`，现已完成，不包含这次修改；不能将它的结果归因于新增字段。新增字段也不证明学习收益，仍需后续冻结对照检验。

## 本轮发现并修复的准入问题

旧规则要求每轮至少一项任务出现收益，同时每项退化不超过容忍值。这个逻辑存在反例：16 项任务，control 的质量均为 0.4；candidate 一项为 0.411，另 15 项为 0.381。局部增益超过 0.01，逐项损失小于 0.02，但平均质量从 0.4 降至 0.382875，旧规则仍会接受。

类似地，一项 solver 从 10 秒降到 5 秒，另 15 项从 10 秒增到 100 秒，总成本从 160 秒升到 1505 秒，局部成本胜出仍可能通过。质量显著改善也不应成为无限增加迭代耗时的理由。

新规则在每一轮独立检查：完整配对、有限有效指标、所有 candidate 正确、逐任务质量保护、整体平均质量不降、solver 和完整 trial 总耗时不突破固定容忍比例；然后才检查整体质量收益、正确性修复或整体成本节省。正确性失败的负数标记不作为数值收益参与平均。新收据包含逐轮汇总，既能审计，也避免用跨轮平均掩盖不稳定表现。

默认 5% 成本容忍是可配置的工程起点，尚无实测噪声依据。每轮两次重复是最低配置，不是统计显著性证明。该规则限制稳定发布，不证明它是最高效的探索准则。

## 已建立的边界及其限度

| 边界 | 当前保证 | 限度 |
| --- | --- | --- |
| 变更权限 | 候选 schema 只接受条件化建议；生产 evaluator、kernel 门槛、预算不属于候选修改对象 | 自然语言建议仍可能让 solver 作出错误选择；最终 full evaluator 和隔离部署仍必要 |
| 结果权威 | 由控制器独立调用 evaluator 并检查收据，不接受 solver 自报成绩 | 可信同用户适配器能访问宿主文件；文件哈希不能抵御恶意同权限进程 |
| 生产路径 | 每轮一次有界本地文件读取，无学习调用或数据库等待；故障回退原路径 | 文本仍增加模型输入，文件读取微基准不代表完整迭代延迟 |
| 后台成本 | 冷却、增量窗口、累计预算、崩溃保留预留额度、独立 GPU | CPU/内存/API 配额共享可能竞争；wall time 不等于 token 或金额预算 |
| 泛化 | 独立路径的冻结任务、重复配对、按 scope 发布 | 路径不同不保证语义不重叠；反复使用固定 suite 会过拟合 |
| 回退 | 谱系、证据审计、停用、恢复上一策略 | 不是对线上效果持续 A/B 的自动回退；后台停止时不会持续发现证据失效 |

暂不扩大到任意自改代码、模型训练、自动调低正确性门槛。这些能力需要新的隔离与评估条件；现阶段加入只会扩大未经验证的变化面。

## 下一步怎样证明“值得使用”

比较应固定任务划分、模型版本、可用工具、生产 solver 预算和总资源预算，至少包括：原始系统、同长度人工固定策略、只检索原始经验、当前局部经验进化。之后加入按官方机制实现并明确适配差异的 ACE / GEPA 基线；具备搜索树记录后再比较 Dream-RSI。不能把简化的检索或反思基线命名成原论文算法。

按算子家族、布局/形状和设备划分学习集、用于选策略的开发集、最终独立审计集。审计集在策略冻结后仅用于最终比较，不能把失败结果反馈给同一轮选择再报为独立测试。模型与硬件变更分别评估迁移，不合并宣称普遍有效。

提前冻结指标与判定方法：

- 正确性与保留能力：逐任务配对结果，所有失败和退化均保留，不能只报总分。
- 产出：固定预算内可晋升 kernel 的比例、质量分布；到达预先设定质量的耗时，超时作为未达成记录。
- 重复犯错：按错误类型、任务条件和已尝试修复共同定义，人工抽查归类，避免把同一报错字符串误认为同一种错误。
- 成本：分别报告生产 wall time、模型 token/费用、GPU 时间、学习和策略验证费用，另报实际并发下的端到端吞吐；不能把并行资源秒数直接当成端到端延迟。
- 不确定性：先用小规模 pilot 估计方差，再固定独立任务数和重复数；置信区间以任务为单位配对重采样，避免把同一任务的多次运行当成独立任务。固定分析次数，不能边看结果边无限补试。

学习一次是否划算，需要在同一种资源成本单位下核对：后续适用任务数 × 单任务平均节省，是否超过学习与验证的额外成本。若只能提升质量，则比较同总预算的质量；不能用独立 GPU 掩盖总账增长。若复杂 RSI 未胜过固定策略或简单检索，应保留更简单的方案。

截至首次设计复核，只有 CPU 闭环与反例测试。随后完成的真实模型/GPU pilot 见下文：它验证了拒绝无收益策略的流程，没有证明学习收益、生产迭代不变慢或方法全面领先。

## 试跑准备中的资源控制反例

用户随后允许在 HyperPod flexible、优先级 80 使用最多八张 GPU，并选择先用 gpt-6-astra 做一张 GPU、30 分钟内的试跑。模型连接测试成功，但开发实例启动期间，独立本地计时器在期限到达后因 DNS 失败退出，未能发出 stop。恢复观察后立即停止并核实空 Pod，创建请求到确认释放的保守计时为 6511.07 秒，超过约定期限。没有完成学习或配对验证，不能将这次资源消耗记为有效实验。

这个反例说明“进程有预算、本地有 watchdog”不足以保证云资源安全。后续试跑改为平台 `activeDeadlineSeconds`、禁止重试的批任务，模型凭据留在本机，任务只接收签名的响应；模型中转连接丢失也会提前结束工作。最初的 1200 秒替代方案仅做预览。用户随后明确批准 90 分钟，实际批次与修复尝试的累计资源账见下文；这不抹去此前超时事故。


## 2026-11-10：真实模型 / B300 小规模试跑

冻结源码 `983f3bd4cf2b93cedea86befdc1408a45d2f8eee`，模型 gpt-6-astra、medium reasoning；HyperPod flexible，1 张 B300、优先级 80。学习任务为 add-scale 和 row-sum，独立路径上的验证模板为 fused-ReLU 和 row-mean，各有连续/跨步布局、两组输入种子。验证为两模板 × 两轮 × control/candidate，共八次独立 full evaluator。Solver 每次只生成一个实现，没有多步工具调用；这只能检查接入、迁移建议和准入流程，不能直接测量“更会安排实验”。模型接口不提供配对随机种子，repeat 标签不能声称是相同的模型随机流。

两项学习任务均通过正确性，但基线加速比分别约 0.633 和 0.504（小于 1 表示更慢）。学习器收到两个 evaluator 事实和两条标为 Agent 解释的报告，提出“发生跨布局、跨批次性能回退时先诊断基线相对延迟”的建议。建议条件还点名了学习任务，能否迁移至验证模板存在明显限制。

| 正确性通过 | 2 / 2 | 2 / 2 |
| 可晋升 kernel 数 | 0 / 0 | 0 / 0 |
| Solver 总耗时 | 42.91 / 48.51 秒（+13.03%） | 39.71 / 44.52 秒（+12.12%） |

这次 90 分钟授权下的三个批次从创建请求到确认释放累计 391.54 GPU 秒（约 6.53 GPU 分钟），均单卡顺序执行。第一批因 quick/full seed 配置不兼容退出，没有模型调用；第二批将 Triton 的正常 `tl.load` 错误拦截，完成一次模型调用后退出；第三批修正适配器，复用第二批的同一回答，不重新抽样，完成全部流程。模型实际调用共 11 次，14,844 tokens。平台报告的 cost 字段合计 0.3040865，币种未独立核验，不据此宣称账单金额。此前独立的 108.5 分钟事故仍另记。

最终批次配置 3600 秒平台硬期限、3300 秒 worker 期限、断联 60 秒退出、零重试、无持久生产挂载。平台预览与 live 配置一致，最终 live Pods 为空；所有批次提前结束，因此没有测试“到期时平台确实杀死任务”的情形。证据压缩包 SHA-256 为 `542021a732b3249cf71cd204eb2fec0143151a1bb65e42495b8ba12ba5a0ab8e`。本地独立重算了十份 evaluator 收据及策略准入结论。结构化记录见 [pilot audit](../audit/rsi_gpu_pilot_20261110.json)。

## 从失败试跑中吸收什么

这轮结果支持保留准入门槛，不支持把策略发布出去。它也暴露出当前输入摘要过粗：只给出“slower”和截断原因，会迫使学习器重复提出“先测量”的泛化建议。后续实现补充了 evaluator 已验证的 baseline/incremental speedup、最多八批固定基线收益、晋升资格及截断标记；缺失和非有限值保留为未知。它只扩充后台有界摘要，仍受 128 KiB 学习输入上限约束，不读取额外历史文件，不改变前台路径。旧证据不被悄悄重写。

另外，验证中的候选与生产建议都使用中性的“Scoped research advice”，避免把尚未通过验证的候选提示称为“Validated”。这会改变 validator 身份，旧收据不能沿用来采用策略。上述两处改动通过 44 项 RSI 测试及全仓 247 passed / 8 GPU opt-in skipped；**尚未再做 GPU 学习收益比较**。CPU 生命周期测试固定其报告的 solver 时间以避开短进程 25 ms 轮询抖动，真实适配器和 evaluator 仍执行，成本门槛由独立数值反例测试覆盖；真实 GPU 数据不做任何平滑或替换。

下一阶段应先让 solver 能在固定预算内实际执行“测量—诊断—改写—再测量”，记录每次假设、选择及失败原因，并与同工具、同预算的无记忆和简单检索版本比较。量化摘要只是更完整的观测，不是已经获得诊断能力。建议适用性、跨任务语义覆盖、最终独立审计集和学习成本摊销仍是未完成项；不应通过反复重跑同一候选、降低门槛或增加策略文字来制造“进化成功”。

## 多步适配器与报告归属复核（2026-11-10）

单次生成 pilot 无法验证实验安排，因此增加了可选的两步研究执行器：相同预算下选择提出候选、quick/full 测量或停止，保留源码、假设和已执行的结果，最终仍由独立 full evaluator 判定。所有对照共用这套工具，不能把执行器本身的提升归因于学习策略。

代码参考核对采用了固定版本：[GEPA candidate selectors，`ce5b0d6`，2026-11-09](https://github.com/gepa-ai/gepa/blob/ce5b0d6e3d6af6c6dbec6de2c54536bbb961d309/src/gepa/strategies/candidate_selector.py) 同时提供 Pareto/current-best/epsilon-greedy 等选择器；本实现仅保留实际尝试并采用 full 通过后的严格改进，没有移植 Pareto 搜索。[Dream-RSI TraceEnv，`8ec35bd`，2026-10-08](https://github.com/google-research/dream-rsi/blob/8ec35bd2538220517ce1bfca4282db21b8c518db/dream_rsi/env/trace_env.py) 的 replay 只揭示已在线评测的节点，并保留父节点可达约束。本实现尚不具备完整搜索树覆盖，因此只记录真实动作，不虚构未执行分支的收益。以上日期是代码版本日期，论文公开日期仍见前表。

首次四组开发比较冻结 `e42f16f`，条件为无历史、固定人工策略、有界原始记录、学习策略。学习器指出报告中的“融合假设”与附带源码不一致。人工检查确认：实验驱动上传了最终恢复的基线源码，却将其附在先前 Triton 尝试的假设上。这是报告归属错误，不是模型没有写出 Triton。试跑因此提前终止，已完成的部分比较不作为干净的策略效果证据；原始结果仍保留，不能删除负面或失败样本。

修复增加了从具体 evaluator 收据和冻结源码生成报告的函数。它验证候选哈希、评测身份和源码归档，显式区分“尝试过的源码”与“最终选择”，拒绝不匹配记录。学习器提出的是诊断建议；本次软件修复经过人工/代码代理核查和测试，没有赋予学习器自动修改执行器的权限。这是一次有用的诊断线索，不是已证明自动 RSI 提效。

该次提前结束还实际验证了远端 60 秒失联退出路径：控制器暂停心跳后，worker 以 `Controller contact lost` 结束、导出证据，控制器恢复后确认 live Pods 为空。一个在暂停前签发的请求因过期返回 403，未放宽签名时间校验。平台硬期限保留，但没有等到期限到达；不能将此次提前退出声称为平台到期终止验收。

## 针对适用性与工具能力的后续改进（2026-11-10）

四组比较暴露了两个可直接验证的设计缺口：原实现把一个 scope 的全部规则发给每项任务，只靠自然语言 when/unless 让 solver 判断；学习器没有得到可用工具的声明，却建议区分 host/device 开销，而受限 solver 并没有独立 profiler。它们是下一轮改进的明确依据，不是学习组退化的已证实原因。

再次核对固定版本的 [Dream-RSI policy API，`8ec35bd`，2026-10-08](https://github.com/google-research/dream-rsi/blob/8ec35bd2538220517ce1bfca4282db21b8c518db/dream_rsi/policy/api.py)：`GridPlanningContext` 明确提供已完成历史、fallback 与硬上限，策略在实际环境协议内决策。可借鉴的是先声明可观察事实与动作边界。本项目据此增加操作者固定的任务标签/能力 profile；没有照搬其搜索空间或开放策略代码。GEPA 的候选选择器保留不同任务上有用的策略，但现有小规模结果还不足以支持移植整个 Pareto 搜索；本轮先处理经验选择的一致性，不宣称实现 GEPA。

规则现在可以声明全部必需标签 `applies_to` 和全部必需能力 `requires`。发布与验证共同调用同一个确定性筛选器，缺失事实不匹配；规则不能新增能力，profile 不由学习器修改。学习器只看到本批证据对应的生产 profile，不看到验证模板的 profile、路径或结果。带 profile 的 scope 要求更新规则显式声明条件，未知或没有任何适用生产任务的建议被拒绝。改变条件算不同策略，但仅重排标签或改规则 ID 不能绕过重复验证限制。

一个容易遗漏的反例是：验证模板一仅启用 A、模板二仅启用 B，生产却会启用 A+B。分别通过不能证明组合通过。新增检查要求每种实际发布的非空组合在至少两项冻结验证任务中出现，缺覆盖时在 GPU 和验证预算预留前拒绝。完整配对质量与成本门槛仍保留；没有缩小到只评测有利样本。即使如此，相同标签与规则组合也不证明工作负载语义相同或真实收益可迁移。

该改进不增加前台模型请求、向量库、历史扫描或权限；筛选发生在后台发布快照与试验准备中。规则总量仍最多六条、2400 字节，不把“有检索机制”当成扩张上下文的理由。自然语言可以错误或遗漏声明依赖，因此标签筛选不能替代实际动作白名单、隔离和 full evaluator。它是针对已发现缺口的工程改进，真实效率收益仍需新对照，之前 `942fd11` 的 GPU 结果不适用于它。


## 扩展价值研究：开发第一轮（2026-11-10）

冻结 `a77bad3`，4 个训练算子产生真实轨迹，4 个开发算子各两轮，control / 原始记录 / RSI 共 24 次尝试，单张 B300，gpt-6-astra。三组最终正确且可晋升均 8/8，但 trial 累计时间分别 445.19 / 451.59 / 319.29 秒，平均质量分别 0.41701 / 0.41416 / 0.38964。RSI 时间少约 28.3%，质量却低约 6.6%，准入全部拒绝；没有发布策略。质量是原有 evaluator 的归一化收益指标，不是正确率。

三组错误候选次数分别 5 / 6 / 2，但按轨迹内错误类别和 dtype 计数的重复事件均为零，不能据此宣称减少重复犯错。学习另耗 30.15 秒、30,950 tokens；验证收费时间 1219.36 秒，全批 836,957 tokens。111 份 evaluator 收据和 71 条源码绑定独立核验通过。创建至确认空 Pods 共 1312.33 GPU 秒，扩展预算累计 3853.53 GPU 秒；较早独立超时事故仍另记。

主要退化出现在 standardize 的一条 RSI 轨迹：观测到 BF16 失败后，把 FP16 也回退到慢实现并停止。control 和另一条 RSI 轨迹保留了 FP16 快路径。这是值得检验的机制假说，不是少量样本已证明的因果关系。新版本补充来自冻结配置和真实收据的失败 case 条件，并要求学习器不能把“正确/可晋升”等同于“继续改进无价值”。这不会强制 solver 多花动作，也不放宽质量门槛。

第二轮是事前允许的最后一轮开发候选：所有组使用同一新版运行时、相同训练档案、工具与四步预算；学习策略重新由模型生成，不能手改规则后称自主学习。开发信息仅用于改进设计，独立审计集仍不参与学习。若两轮均不满足保护质量的实际收益门槛，则停止该研究的候选选择，不反复补样本寻找正结果。结构化结果见 [开发第一轮收据](../audit/rsi_value_development_round1_20261110.json)。


## 扩展价值研究：第二轮及停止结论（2026-11-10）

第二轮冻结 `69e00a6`，所有组共用新增失败条件反馈；仅后台学习器增加证据范围和质量保护要求。相同训练档案、模型、四步工具预算、任务与交错顺序均保留。学习器生成一次三条规则，没有手工修改规则，也没有模型或任务自动重试。

| 组别 | 最终正确 / 可晋升 | trial 累计时间 | 平均质量 | solver tokens | 错误候选 |
| --- | --- | --- | --- | --- | --- |
| 无记忆 control | 8/8 / 8/8 | 448.20 秒 | 0.40661 | 301,399 | 6 |
| 有界原始经验 | 8/8 / 8/8 | 471.46 秒 | 0.40738 | 321,135 | 5 |
| 学习 RSI | 8/8 / 8/8 | 384.15 秒 | 0.39071 | 259,778 | 6 |

质量使用原 evaluator 的固定基线延迟收益：正确且可晋升时取各批 `1 − candidate_latency / baseline_latency` 的中位数；正确但不可晋升记零，失败单列。这里质量低约 3.9%，不是正确率下降，也不是直接表示 kernel 慢 3.9%。每次重复的 RSI 整体质量都低于两个参考组，且有逐任务退化，全部准入拒绝。

RSI trial 时间少约 14.3%，但学习另耗 24.14 秒、31,830 tokens；仅加这笔成本，时间节省已经降至约 8.9%，token 节省约 3.2%，仍未计训练和策略选择。错误候选没有比 control 少；按轨迹内错误类别/dtype 定义的重复事件各组均为零。因此本轮不支持“更少重复犯错”，也不支持“保护质量的净收益”。

轨迹显示，两条 RSI standardize 现在都保留 FP16 快路径，仅对 BF16 使用局部恢复，第一轮那种扩大回退范围的现象没有再次出现。但 RSI 直接选择融合最终点算的版本后停止；control 比较了另一版本，保留更好的实测候选。点算任务仍出现同类 BF16 数值失败。这个观察说明证据更准确不自动等于决策更有价值；少量轨迹和计时变化也不足以把所有差异都归因于停止规则或某一行源码。不能把修复一种行为当作净收益证明。

116 份原始收据、76 条源码绑定、策略筛选、完整配对、模型调用归属和全部准入均离线重算。77 次模型调用全部完成，无缺失 usage，已知 914,142 tokens。平台任务 `42831a44bb6045ee8ce0e9932fe253c3` Completed，live Pods 为空；创建至确认释放 1377.60 GPU 秒。新实现的 49 项 RSI 测试和该提交 Python 3.11/3.12/3.13 CI 通过。工程测试不是收益证明。详见 [第二轮收据](../audit/rsi_value_development_round2_20261110.json)。

新鲜训练加两轮开发共 161 次模型调用、1,883,830 tokens、2924.63 GPU 秒（48.74 分钟）；同一训练档案只计一次。扩展预算累计已确认 5231.13 GPU 秒（87.19 分钟），所有已提交任务释放；早前独立的 108.5 分钟事故另记。完整账目见 [资源账](../audit/rsi_value_study_ledger_20261110.json)。没有将 GPU 时间、模型 tokens 和费用混作一个单位。

按事前最多两轮的规定，本研究到此停止候选选择，不运行只留给合格候选的最终审计集，不增加样本寻找正结果。两轮属于开发比较，不能合并成独立确认试验。分支保留实验性 RSI、事实投影和审计/回退能力，PR 保持草稿，生产策略保持未采用；main 不由本工作修改。结论是**当前文本规则式 RSI 没有达到收益验收要求**，不是所有 RSI 方法都无效。也没有证明比参考算法更好。

随后检查发现，设备空闲探测的 `OSError` 重试分支也可能吞掉一次性定时器的 `TimeoutError`。适配器改用独立异常退出准入/监督流程，在清理后才转换为明确的超时；没有修改通用 Manager 的重试逻辑。新增卡住的设备探测测试确认超时后不会启动子进程，10 项接入专项、72 项相关测试及全仓 533 passed / 10 skipped 通过。上述 CPU 开销样本属于修正前的 `f4be938`，未将它冒充异常分支修正后的新测量。详见 [截止时间修正收据](../audit/rsi_managed_deadline_20261111.json)。

### 源码中值得保留的区别

SciMARS 的 [successor.py](https://github.com/WeiminWu2000/SciMARS/blob/befba7a76667baa456227f94636920408da3c22a/mah2/successor.py) 只复用同一轮、完整 harness 相等且程序哈希匹配的可运行结果，并记录 `executed=false`；这避免把同一次测量算成第二份证据。本项目历史 kernel 面向新配置，仍须当前 full 验证，不能借此取消独立终验。[memory.md](https://github.com/WeiminWu2000/SciMARS/blob/befba7a76667baa456227f94636920408da3c22a/docs/memory.md) 说明每次评测从同一允许的种子库创建独立状态；这支持隔离各试验的经验写入，避免对照之间泄漏。

A-Evolve 的 [StagnationRollback](https://github.com/A-EVO-Lab/a-evolve/blob/96ed93ba7ee0b9519fc55c963afb47a1975eb1ae/agent_evolve/algorithms/unified/verifiers/stagnation_rollback.py) 明确标为可选，未进入 Phase 1 loop recipes，缺少 pass_rate 时放行。因此“仓库存在回滚模块”不能证明每次运行都有有效回滚；也不宜将这种探索用门槛替代 kernel 的缺证据拒绝规则。

SelfImprove-Bench 的 [成本回归测试](https://github.com/theseus-labs-rsi/SelfImprove-Bench/blob/569438708d3de1989ba9cbcd0667bf79d2cc5d30/tests/test_refinement_accounting.py) 保留失败编辑、候选验证及后续选择失败前的已知成本；[token ledger 测试](https://github.com/theseus-labs-rsi/SelfImprove-Bench/blob/569438708d3de1989ba9cbcd0667bf79d2cc5d30/tests/test_token_ledger.py) 还允许显式标记的同任务均值插补。本项目只吸收账目完整性的原则，实际准入继续要求真实 usage，未知成本不插补成已知。其 [恢复等价测试](https://github.com/theseus-labs-rsi/SelfImprove-Bench/blob/569438708d3de1989ba9cbcd0667bf79d2cc5d30/tests/test_resume_equivalence.py) 对比中断前后已提交分数和 token，保留废弃尝试，也值得用于将来的后台发布恢复验证。

### 对设计的直接约束

经验采集应由控制器从真实收据自动完成；agent 的解释另存为未经验证的假设。后台进化器可以整理、提出改动，前台只读取有界的版本化快照。经验内容、调用策略与验收门槛是三个独立对象，学习器不能改写测量结果或放宽自身通过条件。选择器需要当前运行环境观测；不能把历史设备记录冒充当前设备，也不能为了匹配经验偷偷增加一次前台 GPU 探测。

先验证单个机制的净收益，再决定是否建立自动发布、撤回和两代闭环。增加记忆图、编辑器数量或反思频率都有成本；这些论文不能作为无条件扩大架构的依据。本次资料补充不改变正在执行的 `14a3e29` 四组冻结协议、预留确认集或验收规则，不宣称已优于任何参考算法。

质量分数仍为原 evaluator 的固定基线归一化收益，不是 kernel 速度比。因此直接复用的分数比 control 高 7.23%，**不能写成 kernel 快 7.23%**。其完整 trial 时间少 5.59%、token 少 3.72%，两次重复的平均质量均更高，并通过原逐任务、逐轮和成本保护。这是目前最明确的正向开发信号。

为避免将评分误读成速度，另对已关闭实验补作了**事后描述性**核对：在每次试验内保留 objective case 权重和两个测量批次，再对 16 次配对等权取几何平均，直接复用／control 的实际候选耗时比为 1.0461×（对应约 4.40% 时间减少）；最差配对为 0.9662×，仍有局部退化。相对各自固定 baseline 的 speedup 比几何均值为 1.0455×。这些是不同 trial 时点的微基准，包含漂移与噪声，不是生产端到端加速或新增显著性结论，不能替代已冻结的准入。见 [次要耗时指标](../audit/rsi_linked_reuse_secondary_timing_20261111.json) 和 [计算脚本](../audit/rsi_linked_reuse_secondary_timing_20261111.py.txt)。

据此需要区分三件事：**保留研究候选、批准生产策略、证明跨轮统计可靠性**。未达到生产门槛的代码或经验仍可留档，未来在新证据和新登记机制下研究；不能删除旧失败或对相同候选不断重试。已有逐任务／逐重复保护和四算子簇重采样，尚不等于跨代错误接纳率的数学保证。长期发布器还需要预先定义候选尝试数、数据暴露与错误预算，并检查采样假设；这属于待实现、待验证的工作。
