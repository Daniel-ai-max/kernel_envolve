# RSI 代码就绪验收

本次目标是分支代码可交付，不是部署或启动生产任务。默认关闭、保留 main、没有新 GPU 或付费模型任务。工程验收覆盖下列明确支持的接口；不把测试通过写成所有任务上绝无 bug 或已经证明新的生产收益。

## 根据实验固定下来的机制

- 先复用已有实现、重新 full 测量，再使用剩余普通动作继续探索；不默认启用此前未通过质量保护的自适应两步策略。
- 复用资格与全局采用资格分开。登记经验不需要全局 10% 收益，但普通候选仍须当前评测；改变全局默认版本仍走独立 Registry 对照、保留能力与成本门槛。
- 已知失败作用于确切输入配置、运行 scope 和源码；单纯未改善还区分当前起点。失败、中断、未激活、后续修复分别记录。
- 学习使用已有收据，前台保持有界快照。不增加每步反思调用，不用条目数量或源码变动数量代替收益。

## 本轮发现与修复

| 问题 | 修复后的行为 | 验证方式 |
| --- | --- | --- |
| 已预留输出目录在无候选分支被当作新目录 | 在 disabled/无候选等返回前拒绝复用目录；预留历史不因文件缺失消失 | pending/incomplete 两种实际 SQLite 状态回归 |
| 输出目录与 memory/archive 重叠，运行后才收集失败 | prepare 前拒绝目录相等、包含及被包含关系 | 启动前反例与零新增 ticket 检查 |
| 升级后不能查看/停用旧复用库，或能错误重新启用 | 受限 recovery 路径允许只读状态、停用、关闭中断；拒绝新工作和重新启用 | API 与独立 CLI 子进程检查 |
| 未知/已消费 ticket 请求留下孤立反馈文件 | 先校验 ticket 和状态，再持久化反馈与状态变化 | 对数据库和文件清单核验 |
| Registry BEGIN 已生效后被中断，事务未清理 | 只回滚本次拥有且仍活动的事务，不覆盖调用方事务 | 真 SQLite 的 BEGIN/COMMIT 前后确定性中断 |
| Registry 把版本不兼容当作经验失效并撤回，或消耗验证机会 | snapshot/rollback/finish/enable 在状态变更前拒绝不兼容代码 | 对完整数据库转储做前后相等检查 |
| 打开缺失 Registry 生成空库，配置损坏时未关闭连接 | 打开只接受已有文件，初始化失败关闭连接 | 缺失文件及关闭连接检查 |

事务探针复用真实 SQLite 语义：`Connection.rollback()` 在无事务时是 no-op。初期代理不匹配该语义产生的一个假阳性不计作产品缺陷；实际复现的 BEGIN 后中断泄漏已修复。

## 第二轮缺口审查

继续检查完整状态链后，以下缺口通过失败用例复现并修复，不能以第一轮 CI 通过推断它们原本不存在。

| 缺口 | 修复后的行为 |
| --- | --- |
| Registry 审计/生成快照期间停用或回退，仍返回旧快照 | 在短事务内复核 enabled/active 后才完成解析；不一致返回无经验 |
| 旧版本审计失败时，错误撤回另一个连接刚恢复的新 active | 自动回退绑定被审计的版本，事务内再次比较；后台重解析有次数上限 |
| 畸形 JSON 证据把准入卡在 checking | 明确写入 rejected，保留至少预留额度；合法部分中的已知超支仍扣账。不可归档输入在状态变化前拒绝 |
| 打开文本 RSI 状态时自动创建丢失的数据库或缺失的表 | 只有 initialize 创建数据库。正常打开必须有完整 schema 和配置哈希，否则拒绝，不重置预算 |
| 停用与实验预检重叠，后续仍能预留新工作 | reserve 的事务内检查 enabled；已预留/正在执行的工作仍由外层停止 |
| 非法耗时或真假值写入预算/启用状态 | 耗时只接受有限非负数，启用值只接受布尔值；非法输入不改变账本 |

并发回归使用两个真实 SQLite 连接，在审计及快照生成的确定性位置执行停用/回退，核对活动指针、历史和返回值。预算及状态损坏测试核对操作前后的完整数据库内容。修复前共 21 个失败用例，另补不可归档输入与事务提交前再次切换的边界回归。见 `audit/rsi_gap_review_20261111.json`。

健康的文本 RSI schema 1 状态可直接重新打开；丢失数据库、缺表、缺配置哈希或只有 config/owner 的不完整初始化目录必须恢复原始一致备份，不能补空库继续运行。初始化现在创建并校验数据库后才成功返回。Registry 的本轮修复再次改变验证器身份，沿用下述冻结旧代码/重新验证的迁移约束。

## 支持范围与使用方式

经验源码复用当前支持单文件 generic `task.py` / `candidate.py`、完整实际评测记录、同一主机路径，以及明确的 profile/runtime scope。已有文本 RSI 保持原 generic/native 接口；不能据此宣称新源码复用也支持 native 多文件构建或远端路径迁移。Manager/OS 负责资源隔离和进程生命周期，RSI 不授予模型新权限。

[复用接口与命令](rsi-reuse-memory.md) 包含 init/register/prepare/observe/status/disable/abandon 的完整操作顺序。命令本身不调用模型或 evaluator。生产 Manager 自动成果挂钩不在本次新增范围内；使用者可通过已有研究适配器显式接入，不存在隐式激活。

升级涉及验证器身份变化。保留旧原始档案与旧版代码；新版本拒绝不兼容证据，不会把旧成果标成质量失败。可用恢复命令停用旧库、关闭已终止工作的 pending；需要继续使用旧证据时由冻结旧版审计，迁移不得只改哈希。不要在运行中原地覆盖控制器代码。

## 验收依据

验收记录需绑定最终源码、测试日志和准确提交的 CI；见本轮生成的 `audit/rsi_readiness_20261111.json`。要求完整本地回归、相关生命周期测试、发行 wheel 的独立安装和命令验证、Python 3.11/3.12/3.13 CI 全部通过。修复前失败日志保留，以区分真实回归与测试配置或探针问题。

后续缺口修复以 `audit/rsi_gap_review_20261111.json` 绑定更新后的源码及安装包；独立安装同时验证源码经验库和文本 RSI 的 init/status/collect/disable/enable、预算重开持久化，以及丢失数据库不会被 status 重建。安装验证不调用模型或启动 Manager worker。

旧实验的实证结论仍见 [收尾报告](rsi-closeout-20261111.md)：有经验复用的正面观察，尚未确认长期净收益。此次代码验收不改写旧门槛、失败判定或费用账，不恢复 GPU 使用。
