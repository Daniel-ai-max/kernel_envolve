1. Inventory the workspace and resolve the kernel, reference, inputs, knowledge and custom benchmark. Present a short resolved plan. The task and contract are already fixed; use candidate.py as the solution and gpu.py as the user-provided benchmark. Initialize git if necessary and create opt/<task>.
2. Persist the common constraints in HINTS.md. Verify the baseline candidate using the common evaluator, expect correctness pass, then commit the baseline. Probe python3 gpu.py profile --target baseline once to inform the first optimization. If unavailable, use analytical reasoning and runtime statistics for the rest of the session without repeated probing.
3. Iterate profile/analyze → modify candidate.py → benchmark → log → commit. Each modification followed by a benchmark is one iteration. Immediately after that benchmark, the next two tool calls must (a) append its structured ITERATIONS.md entry and (b) git commit -m "[iter N] <direction>". Include failed/partial benchmarks; log and commit before debugging, profiling or reading for the next direction. Log the source, hypothesis, result/run ID, runtime/correctness and next direction. Group related experiments in prose, not by skipping commits.
4. Keep iteration feedback cheap using only the switches exposed by this custom evaluator. Candidate-only quick signal can rank candidate latency but is not speedup. Use a full run with measured comparator and complete checks before declaring a winner; promote successful full results. Do not change trial counts, input regime or the evaluator to make a result pass. Do not cache comparator latency across unlocked-clock iterations.
5. After three consecutive iterations without at least 3% improvement over current best, reassess: profile if available (otherwise inspect runtime distributions), consult op-specific techniques for this hardware, and review ITERATIONS.md. Choose a new direction unless evidence shows a physical floor. Do not stop simply because a tool is unavailable. Try meaningful implementation changes; stay within the explicit eight-minute cap.
6. Stop when the budget expires, a measured physical floor is demonstrated, or at least three distinct viable directions have been exhausted. Restore the exact best source from its git commit or saved best snapshot, never reconstruct it manually. If restoring a prior iteration, run a fresh full sanity check when time remains and commit the restoration. Write the chosen exact source to submission.py before the deadline.
